Active Member
สมาชิกที่มีบิลอย่างน้อย 1 ใบ ที่สาขานั้น ภายใน 30 วันล่าสุด (rolling) — ไม่ใช่ยอดสมัครสะสม เป้า 4,000 คนคือค่านี้ ณ D90
ลูกค้าใหม่ / ลูกค้าเดิม
ตัดสินสถานะ ณ วัน GO แล้วล็อกตลอด 90 วัน — ลูกค้าเดิม = มีรหัสสมาชิก CJ ก่อนวัน GO, ลูกค้าใหม่ = สมัครตั้งแต่วัน GO เป็นต้นไป คนหนึ่งคนเปลี่ยนกลุ่มระหว่างทางไม่ได้
D+n
นับจากวัน GO ของสาขานั้นเอง D0 = วันแรกของงานเปิด เพราะเปิดพุธและศุกร์ D30 จะตกคนละวันปฏิทิน ทุกกราฟจึงใช้แกน D+n
หน้าต่างวัดผล
W1 = D5–D30 (สำหรับฐาน GO), W2 = D31–D60, W3 = D61–D90 (เป็นช่วง ไม่ใช่จุด) ส่วน "ผลตัดยอด" คือค่า ณ วัน D30/D60/D90 พอดี รายงานทั้งสองแบบคู่กันเสมอ
กลับมาซื้อซ้ำ (Return)
% ของฐานตั้งต้นที่มีบิลอย่างน้อย 1 ใบในหน้าต่างนั้น หลังบิลใบแรกและหลังงานเปิดจบ (D5) ฐานตั้งต้นหลักคือคนที่ซื้อช่วง D0–D4 หน้าต่างแรกจึงเป็น D5–D30
ความถี่ (Repeat frequency)
จำนวนวันที่มีบิลเฉลี่ยต่อคน เฉพาะในกลุ่มที่กลับมาจริงในหน้าต่างนั้น รายงานคู่กับ % return เสมอ เพราะ % สูงแต่ความถี่ต่ำ กับ % ต่ำแต่ความถี่สูง ต้องแก้คนละทาง
เส้น Pace
ไม่ใช่เส้นตรงจาก 0 ถึง 4,000 ฐานลูกค้าใหม่จะพีคราว D30 แล้วหลุดออกตามธรรมชาติ เกณฑ์ที่ใช้คือ D30 ต้องได้ 118% ของเป้า D60 ต้องเหลือ 108% จึงจะเหลือ 100% ที่ D90 — ถ้า D30 ได้แค่พอดีเป้า แปลว่าพลาดแน่แล้ว ต้องแก้ตั้งแต่ตอนนั้น ไม่ใช่รอ D90
ผลกิจกรรม
Active 7 วันหลัง ลบ ค่าที่ควรจะเป็นถ้าไม่ทำอะไรเลย (= Active 7 วันก่อน คูณอัตราการลดของ 2 สัปดาห์ก่อนหน้า) ที่ต้องหักแนวโน้มออกเพราะฐานลูกค้าใหม่ลดเองอยู่แล้ว ถ้าเทียบดิบๆ กิจกรรมทุกตัวจะดูเหมือนไม่ได้ผล ต้องบันทึกค่าใช้จ่ายทุกกิจกรรมตั้งแต่วันจัด ไม่ใช่ย้อนหาทีหลัง
